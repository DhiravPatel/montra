# Montra — Background Jobs

Durable jobs live in PostgreSQL (ADR-008). The worker process
(`cmd/worker`, role `montra_worker`) runs three loops: the job worker,
the outbox relay and the scheduler.

## Guarantees

- **At-least-once delivery.**
  - Workers claim jobs with `FOR UPDATE SKIP LOCKED`, hold a lease
    (default 5 min) and renew it every lease/3.
  - When a worker dies, its expired leases are re-queued, or dead-lettered
    if attempts are used up.
  - Every handler must therefore be idempotent. Handlers use dedupe keys,
    unique constraints, status checks under row locks and "already done"
    short-circuits.
- **Retries:**
  - Exponential backoff with full jitter: 5 s × 2^(attempt−1), capped at
    1 h, plus 1 s.
  - Max attempts default to 8 (per job via `Spec.MaxAttempts`).
  - `jobs.Permanent` errors skip retries.
  - Exhausted jobs become `dead`; an operator can re-queue them with
    `jobs.Retry`.
- **Dedupe:** `jobs.dedupe_key` is unique. Enqueue is a no-op when the
  key exists, so outbox replays and scheduler restarts cannot double-enqueue.
- **Timeouts and concurrency:** set per job type (table below). The
  worker never runs more than the per-type concurrency at once.
- **Scheduler:**
  - One leader at a time, via a PostgreSQL advisory lock.
  - Each periodic job is enqueued with a time-bucketed dedupe key.
  - Handlers process everything due up to "now", so one run after
    downtime recovers missed buckets (tested for recurring generation and
    integration schedules).
- **Outbox:**
  - Domain writes emit `outbox_events` in the same transaction.
  - The relay turns them into jobs through registered routers (dedupe
    keys derived from the event), then marks them processed.
  - Processed events are deleted after 7 days.
- **Identity:**
  - Jobs that act for a user carry `user_id` and run user-scoped work
    as that user (identity context, RLS-enforcing app pool where reads
    must be scoped, e.g. reports).
  - The API role can enqueue only jobs for the signed-in user.
  - The single exception is webhooks: `montra.enqueue_webhook_event`
    queues only verified, waiting events (ADR-048).

## Objectives (planning targets, ADR-025)

| Class | Examples | Objective |
|---|---|---|
| User-visible, interactive | `imports.parse/normalize`, `receipts.extract`, `reports.generate`, `integrations.sync` (manual) | p95 start < 30 s after enqueue; progress visible in the resource status |
| Notifications | `notifications.deliver`, `*.notify_*` | p95 < 60 s outside quiet hours |
| Ledger-affecting | `recurring.generate`, `groups.sync_*`, `imports.process`, `imports.rollback` | exactly-once effects through unique keys; recovery within one schedule interval after downtime |
| Maintenance | `platform.retention_cleanup`, `files.cleanup`, `privacy.deletion_due` | completes within its interval; bounded batches |
| Fan-out | `subscriptions.detect_all`, `insights.generate_all`, `integrations.schedule`, `notifications.digest_scan` | enqueue per-user work with dedupe; no long transactions |

## Operations

- Metrics (Prometheus, `/metrics` with the metrics token):
  `montra_jobs_processed_total` (type, outcome),
  `montra_job_duration_seconds`, `montra_job_retries_total` and
  `montra_job_queue_depth` (status).
- Stuck work: leases recover crashed workers automatically. Integration
  runs abandoned for more than 2 h are failed by `integrations.schedule`.
  A report whose generation fails on its last attempt is marked `failed`
  with an `error_code` by the handler; reports whose job ended without a
  result (dead after an expired lease, or cancelled) are failed with
  `generation_failed` by the hourly `reports.schedules` run.
- Dead jobs: inspect `jobs` (`status = 'dead'`, `last_error_code`)
  as the worker or owner role. Error messages are redacted codes; payloads
  hold IDs, not personal data.
- Retention (ADR-021, `platform.retention_cleanup`, hourly):
  - deleted after the stated period: login attempts 2 days, expired auth
    tokens 7 days, sessions 90 days, finished jobs 14 days, processed
    outbox events 7 days, webhook events 30 days, integration sync runs
    180 days;
  - idempotency keys deleted when they expire;
  - security events kept for the configured period;
  - expired reports marked expired.
